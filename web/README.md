# Sentinel Dispatch

Build a sleek, production-grade, human-designed React/Tailwind web app for an Autonomous Multi-Agent Emergency & Service Dispatch System. 

### Design Direction (Avoid AI clichés):
- Tone: High-trust, professional, modern mission-control aesthetic (similar to Linear, Vercel, or modern government/health tech platforms).
- Color Palette: Deep slate/neutral zinc foundations (`zinc-900`/`zinc-950` or crisp off-white `zinc-50` with subtle borders `zinc-200`/`zinc-800`). Use precise functional accent colors: Emerald (User), Amber/Orange (Fire/Rescue), Sky/Teal (Hospital), Indigo/Violet (Admin Orchestrator).
- Typography & Layout: Clean sans-serif (`Inter` or `Geist`), compact tabular data, subtle subtle micro-borders, clean badge indicators, and zero generic purple neon gradients.

---

### Route Architecture & Navigation:
Set up proper React Router paths (no tabs for primary page switches):

1. `/login` — Unified Authentication Hub:
   - Split layout: Left column showcases system status with live agent activity pulse ("Agentic Dispatch Network: Active - 4 Nodes Online"). Right column hosts the login card.
   - Login form with email/password and a distinct "Role Selection" or quick-switch demo toggle:
     • "Civilian / User" (routes to `/user/alex-morgan`)
     • "Emergency Service: Hospital" (routes to `/service/city-general-hospital`)
     • "Emergency Service: Fire & Rescue" (routes to `/service/metro-fire-station-4`)
     • "System Admin & AI Orchestrator" (routes to `/admin/dashboard`)
   - Include realistic validation, smooth button transition, and a mock "Demo Quick Login" bar at the bottom for instant hackathon walkthroughs.

2. `/user/:username` — Citizen Incident & Request Portal:
   - Header with user avatar, location status, and connection to active coordinator agents.
   - Main card: "Report Incident / AI Assistance" with an interactive, end-to-end multi-agent triage input (voice/text, image attachment preview, automatic priority detection badge).
   - Live Request Tracker: Step-by-step agent workflow progress bar (e.g., `Vector Memory Lookup` -> `Agent Triage` -> `Unit Dispatched: Ambulance #12` -> `ETA: 6 mins`).
   - History of past service interactions with timestamps and status chips.

3. `/service/:serviceId` — First Responder / Service Console:
   - Support dynamic view based on service type (e.g., Hospital vs. Fireforce):
     • Hospital View: Live incoming patient feed, critical care bed occupancy, RAG-assisted trauma briefing generated by field agents.
     • Fire & Rescue View: Dispatch telemetry, unit availability (Hazmat, Engine 3), GIS/Map zone card with active alerts.
   - Quick action bar: "Acknowledge Dispatch", "Re-route Autonomous Drone/Fleet", "Update Capacity".
   - Mini terminal/feed drawer: "Autonomous Agent Logs" showing real-time autonomous routing decisions.

4. `/admin/dashboard` — Autonomous Agentic Mesh & Pipeline Control:
   - Top metrics: Total Autonomous Workflows Executed, Active Agent Count, Mean Resolution Time, Vector Memory Hit Rate.
   - Multi-Agent Orchestration Visualizer: Interactive node diagram or card list displaying active agents (e.g., `TriageAgent-01`, `DispatchRouter-v2`, `ResourceMemory-RAG`, `NotificationBot`).
   - Pipeline Health & Vector Store Status: RAG latency, context window utilization, and override toggle ("Human-in-the-Loop Intervene").
   - Live system audit log stream with filterable severity levels.

---

### Implementation Details:
- Use Lucide React icons, shadcn/ui primitives, and `framer-motion` for subtle, fluid transitions between routes.
- Populate with realistic, contextual mock data ready for demonstration.

Add an "Emergency Profile & Incident Dispatch Form" to the citizen portal at `/user/:username`. The data collected here serves as structured context and vector memory for the downstream autonomous agents (hospital triage, fire dispatch, paramedic teams).

### 1. Persistent User Emergency Profile (Modal or Collapsible Card)
Add an expandable "Medical & Emergency Profile" card (or quick-edit drawer) that saves critical static data:
- Personal Essentials: Full Name, Blood Group, Age, Primary Language, Emergency Contacts (Name, Relation, Phone).
- Medical Profile: Chronic Conditions (e.g., Asthma, Diabetes, Cardiac history), Known Allergies (e.g., Penicillin, Latex), Current Medications, Implanted Devices (e.g., Pacemaker).
- Residential / Access Info: Home Address, Gate Access Code / Entry Instructions, Mobility Issues (e.g., Wheelchair user, Bedridden).
- Visual Status Indicator: A badge showing "Profile Ready for Agent Context Injection" with a toggle to control data sharing consent.

---

### 2. Live Incident Submission Workflow
Build a high-stakes, distraction-free submission interface at the top of `/user/:username`:

- Incident Type Selector: Quick-select pills with crisp icons:
  • Medical Emergency (triggers Hospital / EMS agents)
  • Fire / Hazard / Gas Leak (triggers Fire & Rescue agents)
  • Rescue / Trapped / Disaster (triggers Joint Response)
  • Other / General Assistance

- Dynamic Details Input:
  • Location: Auto-fill "Current GPS Location" with an editable landmark/floor/apartment field.
  • Incident Description: High-visibility text area with quick-fill severity chips ("Unconscious", "Severe Bleeding", "Smoke Visible", "Trapped Inside").
  • Hazards & Building Notes: Hazards present (e.g., Oxygen tanks on-site, flammable materials, pets inside).
  • People Count: Number of individuals affected.
  • Media Attachment: Quick upload preview for scene photo or audio note.

- Direct Payload Preview:
  • A collapsible preview box titled "Agent Context Payload Preview" showing how this submission merges static medical data + live incident details into a structured JSON/prompt format before dispatch.

---

### 3. Immediate Post-Submission State:
When "Dispatch Autonomous Agents" is clicked:
- Instantly switch the UI into a live **Agent Action Telemetry View**:
  1. `Context Ingestion`: Vector memory combined with static profile.
  2. `Multi-Agent Review`: Triage Agent -> Dispatch Agent -> Hospital/Fire Alert.
  3. `Dispatch Confirmation`: "Payload transmitted to [City General Hospital ER] and [Metro Fire Station 4]".
  4. Real-time ETA banner and emergency call fallback button ("Call 112 / 911 Direct").

---

### UI Style & Components:
- Clean shadcn/ui components: Form controls, Tabs, Badges, Accordion, and Dialog.
- Colors: Soft slate/zinc backdrop with high-contrast alert indicators (rose/amber badges for critical medical notes).
- No generic AI sparkle designs; keep it clinical, tactical, and rock-solid.
